# Sicurezza

## Versioni supportate

Salvo diversa indicazione nel `SECURITY.md` del singolo repository, si corregge
l'ultima revisione del ramo `main` e l'ultimo rilascio pubblicato.

## Segnalare una vulnerabilità

Non aprire una issue pubblica. Usa la segnalazione riservata di GitHub: dal
repository interessato, scheda **Security** → **Report a vulnerability**. La
segnalazione resta visibile solo a chi mantiene il repository finché la
correzione non è pubblicata.

Nella segnalazione indica:

- cosa succede e quale impatto ha;
- come riprodurlo (passi, versione o commit, sistema operativo);
- se il problema è già pubblico altrove.

Non allegare chiavi private, token o dati reali di terzi: bastano i passi per
riprodurre.

## Tempi

Il progetto è mantenuto nel tempo libero: si punta a una prima risposta entro
pochi giorni e alla correzione appena pronta. Chi segnala viene citato nel
changelog, se lo desidera.

## Ambito

Rientrano le vulnerabilità nel codice del repository. Non rientrano i problemi
delle dipendenze di terze parti (da segnalare a chi le mantiene) né quelli che
richiedono già l'accesso completo alla macchina o all'account dell'utente.
